# FinEvalKit Agent Auditor — Frontier Engineering Challenge 2026

## User, bottleneck, and narrow solution

The user is an AI/ML or risk team preparing a financial-document RAG or tool-using agent for
deployment. Manual review is slow, while a mean score can hide a single catastrophic numerical,
citation, privacy, leakage, OCR, conflict, or authorization failure.

Agent Auditor consumes a privacy-safe evaluation case containing an output, evidence identifiers,
and an optional trace. Expected values and evidence metadata are evaluator inputs, not fields
available to the system under test. It uses those audit-bundle signals to plan relevant checks, executes them, verifies
each finding by deterministic replay, and either passes the case or writes it to a human-approval
queue. It never calls a live financial system. The design is intentionally local, inspectable, and
small: one standard-library module, one 12-case JSONL benchmark, one CLI command, and four artifacts.

## Baseline and agent design

The fair baseline runs the same two fixed checks on every case: citation validity and the trace's
authorization Boolean. It averages those scores and escalates below 0.75. This resembles the
aggregate-checklist behavior the project is intended to improve, while remaining useful enough to
catch an invalid citation and a plainly unauthorized action.

The Agent Auditor chooses among citation, numerical, OCR, conflicting-evidence, authorization,
privacy, and split-leakage checks. Every finding is replayed once before escalation. Every trajectory
identifies six roles: audit coordinator, risk router, check specialist, finding verifier, review gate,
and reporter. It records the instruction, selected tools, responses, feedback/retry, verification
summary, human checkpoint, and final disposition. Queue records include privacy-safe evidence, the
requested decision, action policy, and trajectory pointer. The queue requests a human decision; it
does not approve or perform an action.

## Checked results

Generated by the exact reproduction command below on the 12 checked-in cases (9 critical, 3 safe):

| Method | Critical-failure recall | False negatives | False-negative rate | False positives | Workflow events | Runtime/cost units |
|---|---:|---:|---:|---:|---:|---:|
| Fixed aggregate baseline | 0.222 | 7 | 0.778 | 0 | 24 | 24 |
| Agent Auditor | 1.000 | 0 | 0.000 | 0 | 105 | 45 |

`Workflow events` describes each method's inspectable trace and is not an apples-to-apples effort
measure. `Runtime/cost units` are comparable and deterministic: one per check execution, including
verification replay (two per baseline case). They are proxies, not dollars or human-minute claims.
The checked run recorded 24.585 ms of in-process wall time on Python 3.12.13, with zero network and
model calls; wall time varies by host, while 24 versus 45 runtime units reproduce exactly.
The difficult `ocr-sign-and-scale` case turns `(81.00)` into `8100`; independent numerical and OCR
checks both confirm it before escalation.

The authoritative results are `benchmarks/results/agent-auditor/agent_audit_report.json`; the
Markdown report is a rendered summary, not a separate claim.

## Improvement changelog

1. **Baseline — fixed aggregate checklist.** Two uniform checks produced 0.222 critical recall and
   seven false negatives. This establishes the simple comparison rather than using an empty strawman.
2. **Rejected experiment — run every check on every case.** The benchmark contains seven check
   types. Running all seven on 12 cases requires 84 check invocations. Risk routing selects 35 while
   covering every labelled risk type, so run-all was removed as needless work. The computed counts
   are stored in the report's `planning_experiment` field.
3. **Risk-routed planner.** Observable payload signals select checks and preserve the rationale in
   every trajectory. This catches sign/scale, OCR, conflict, confirmation, privacy, and leakage cases
   hidden by the aggregate.
4. **Verification and human checkpoint.** Each initial finding is replayed; only confirmed critical
   findings enter the queue. This raises the proxy cost to 45 units but makes escalation evidence
   explicit and keeps all consequential actions sandboxed.

## Reproduce in a clean environment

Requirements: CPython 3.10 or newer; no API key, model, network access, or non-public data. The
checked run used Python 3.12.13, setuptools 84.0.0, pytest 9.1.1, and Ruff 0.16.5. The input is
`data/agent_auditor_cases.jsonl` with SHA-256
`f6802899f92931082d183567e4556f467c6d2398ebe68823b2968e941508f63e`; the report records this hash
and check schema version 2. From a fresh clone:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install "setuptools==84.0.0" "pytest==9.1.1" "ruff==0.16.5"
python -m pip install -e .
pytest
fineval agent-audit --cases data/agent_auditor_cases.jsonl --output-dir benchmarks/results/agent-auditor
ruff check src tests
```

Without installation, the demo can run using only the standard library:

```bash
PYTHONPATH=src python -m finevalkit.cli agent-audit --cases data/agent_auditor_cases.jsonl --output-dir benchmarks/results/agent-auditor
```

PowerShell equivalent: `$env:PYTHONPATH='src'; python -m finevalkit.cli agent-audit --cases
data/agent_auditor_cases.jsonl --output-dir benchmarks/results/agent-auditor`.

Expected console summary: `baseline recall=0.222; agent recall=1.000`. Expected outputs:

- `agent_audit_report.json` and `agent_audit_report.md`
- `trajectories.jsonl` (12 records, one per case)
- `human_review_queue.jsonl` (9 awaiting-review records)

Approximate in-process runtime is under one second on a typical laptop after Python startup. Runtime
cost is zero paid model/API calls and 45 deterministic runtime/cost units. Re-running overwrites only the specified
output directory's four named files.

## Failure mode and hot take

The main failure mode is **specification blindness**: routing and checks can only detect risks made
representable in the case payload and benchmark. A novel semantic contradiction or cleverly
obfuscated personal identifier can pass. Production use needs independently labelled, issuer- and
time-diverse cases plus sampled human review; 12 deterministic cases demonstrate mechanics, not
generalization.

**Hot take:** a boring, replayable escalation with the right evidence is more valuable in financial
AI than an impressive aggregate score that cannot identify which unsafe answer to stop.
